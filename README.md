## 실습 설계 원칙

노트북은 **동작하는 상태로 제공한다.** 학생은 먼저 그대로 실행해 결과를 확인하고,
표시된 **한 지점만** 바꿔 무엇이 달라지는지 본다. 밑바닥부터 작성하게 하지 않는다.

매 주차 돌아가는 결과물을 손에 쥐고 나가는 것이 목표다.

## AGENTS.md 해설

사람용 해설본. 에이전트 지시 정본: [AGENTS.md](AGENTS.md).

- 2026-10-11, 9-10주차의 설명이 정의·주의사항 중심으로 축약되고 공통 섹션 순서·접힌 Q&A·마지막 실습 절이 누락되어 1-8주차와 품질 차이가 발생. 강의 구성 계약은 이 차이를 바로잡은 사용자 교정의 반영
- 일반 실습의 한 지점 변경과 관찰형의 실행·해석은 수업계획서에 공존하는 활동 방식. Phase 3 이슈 #4의 10·11·13주차와 기존 8주차 노트북에 관찰형 예외 존재. 10주차의 자동 리뷰가 일반 TODO 규칙만 적용한 사례에서 이 구분이 지침에 명시되지 않은 문제 확인
- 같은 작업의 PPO 비교식과 PRIME 접두 기호가 MDX에서 태그로 해석되어 빌드가 두 차례 실패. 수식의 의미와 Markdown·JSX 표기 구분이 실제 빌드에서 확인된 결함
- Phase 3 이슈 #4의 15주차는 최종 발표·데모 활동이며 새 노트북이 없는 주차. 일반 강의의 말미 Colab 구성을 기계적으로 적용하는 것과 정본의 활동 방식 사이의 차이 확인

- 2026-10-11, 전체 검수에서 수동 예시를 실제 원본 자료로 읽을 위험, 지시문과 서식을 함께 바꾼 실험의 통제 설명, 부분 문자열 지표의 의미가 여러 주차에서 반복해 확인됨. 교육 예시·proxy·실측의 구분과 실제 변경 조건 표기는 이 결함을 반영
