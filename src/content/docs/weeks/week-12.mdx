## 온라인 (2시수)

### 강의: 설명과 내부 계산의 구분

□ 왜 설명의 길이보다 평가 대상을 먼저 정하는가

- 제주 공개 정보에 대해 "세 행정시이므로 세 곳"이라고 일관되게 설명한 답은 읽기 쉽지만 사실 오류 존재
- 반대로 "세 행정시"라고 설명한 뒤 "두 곳"이라고 답한 경우 마지막 답만 보면 오류를 놓치는 상황
- 운영에서 필요한 검토: 답을 사용할 수 있는지, 근거 문장을 믿을 수 있는지, 그 설명이 실제 원인을 보여 주는지라는 서로 다른 질문
- 순서: 외부 출처로 사실 확인, 서술과 답 연결 확인, 내부 원인에 대해서는 추가 실험 근거가 없으면 판단 보류

□ 추론 정확도(reasoning correctness)

- 출력된 설명의 사실, 계산, 논리 연결이 맞는지 검토
- 중간 단계에 근거 없는 가정이 끼어 있지 않은지 확인
- 평가 대상: 사람이 읽을 수 있는 **출력 텍스트**
- 내부 계산의 모든 단계가 외부 텍스트에 실렸다는 가정 불필요

□ 답 정확도(answer correctness)

- 마지막 답이 외부의 확인 가능한 정답과 맞는지 검토
- 공개 사실 질문: 출처, 판 번호, 확인 시점의 일치 필요
- 정책 질문: 평가 기준과 이해관계자의 합의가 선행되어야 하는 경우 존재
- 맞는 결론에 도달했어도 설명에 잘못된 근거가 포함될 수 있는 구조

□ 충실성(faithfulness)

- 출력 설명이 실제로 답변을 만들어 낸 계산이나 영향 요인을 반영하는 정도
- 문장이 매끄럽다는 사실과 다른 평가 대상
- 정답과 설명이 모두 맞아 보이더라도 충실성 확인 불가
- 출력 텍스트는 또 하나의 생성물. 내부 계산의 완전한 기록이라는 보장 없음

□ 세 질문을 한 점수로 합칠 때의 손실

- 설명이 길면 신뢰 점수를 올리는 방식: 불필요한 설득력 보상 가능
- 정답만 보면 설명 속 오류를 놓치는 방식
- 서술 일치만 보면 정답 여부와 내부 영향 요인을 놓치는 방식
- 이번 주의 선택: 서로 다른 열에 기록하고, 측정하지 않은 항목은 **미측정** 표시

| 작성 교육 예시 | 설명의 사실성 | 마지막 답 | 내부 충실성 |
|---|---|---|---|
| 제주시와 서귀포시라고 설명하고 두 도시라고 답변 | 이 예시 범위에서 맞음 | 맞음 | 미측정 |
| 세 도시라고 설명하지만 두 도시라고 답변 | 틀림 | 맞음 | 미측정 |
| 두 도시라고 설명하지만 세 도시라고 답변 | 맞음 | 틀림 | 미측정 |
| 세 도시라고 설명하고 세 도시라고 답변 | 틀림 | 틀림 | 미측정 |

- 공개 사실 문맥: [위키백과 「제주특별자치도」](https://ko.wikipedia.org/wiki/제주특별자치도)의 제주시·서귀포시 행정구역 설명
- 위 표의 응답은 교수 작성 예시. 실제 모델 실행 결과 아님
- 사실 질문에서의 설명 정확성도 전체 추론 능력을 평가하는 지표는 아님

### 논문이 보여 주는 것과 이번 실습의 범위

□ 입력 편향과 설명

- Turpin 외의 실험: 선택지 순서 등 입력 편향이 답변에 영향을 주어도 설명에 그 영향이 나타나지 않는 경우 보고
- 관찰 대상: 특정 모델, 프롬프트, 과제 조건에서의 반응
- 모든 설명이 항상 거짓이라는 일반화 금지
- 설명이 답을 만든 원인을 빠짐없이 공개한다는 전제의 재검토 필요
- 근거: [논문 원문](https://arxiv.org/abs/2305.04388), 이번 실습에서 논문의 모델 실험 재현 없음

□ 이번 실습의 작은 프록시

- 프록시(proxy): 직접 측정하기 어려운 대상과 관련된 좁은 관찰 신호
- 관찰: "설명에서 주장한 행정시 수"와 "최종 답에서 주장한 수"의 불일치
- 불일치가 있으면 서술과 답의 연결을 재검토할 이유 발생
- 불일치가 없다고 내부 계산에 충실하다는 결론 불가
- 설명과 답이 같은 오류를 공유하면 프록시를 통과하는 한계
- **서술-결과 불일치율은 내부 계산의 faithfulness 측정값이 아님**

- 관찰 질문: 불일치가 없는 D가 왜 정답 검사를 통과하지 못하는지 예상

- 그림 해석: 비교기는 숫자 사이 관계만 확인, 내부 계산으로 향하는 관찰 경로 없음

### 학습활동: 제공된 서술-결과 비교표 실행

□ 실행 순서

1. 제공된 공개 문서의 출처와 판 번호 출력 확인
2. 네 개의 작성 예시에 대해 설명 숫자와 답 숫자 비교
3. 정답 여부와 불일치를 다른 열로 출력
4. 내부 충실성 열은 모두 미측정으로 유지
5. 불일치 없는 오답 사례와 불일치 있는 정답 사례 비교

□ 판정 표 읽기

- 예시 A: 설명 2, 답 2. 불일치 없음, 답 정확
- 예시 B: 설명 3, 답 2. 불일치 있음, 답 정확
- 예시 C: 설명 2, 답 3. 불일치 있음, 답 부정확
- 예시 D: 설명 3, 답 3. 불일치 없음, 답 부정확
- 네 작성 예시의 불일치 2건은 데이터 구성 결과. 실제 모델의 성능 추정치 아님
- 규칙 기반 숫자 비교는 문장의 의미 전체나 인과 구조를 검증하지 않는 한계

○ 예시 B를 코드 한 줄씩 추적

```text
reference_count = 2         공개 사실에 대응시킨 교육 기준
reason_count = 3            작성 설명에서 주장한 수
answer_count = 2            작성 마지막 답에서 주장한 수
reason_count == 2 -> False  설명의 숫자 주장 부정확
answer_count == 2 -> True   마지막 답 정확
reason_count != answer_count -> True
```

- 불일치 검사는 설명의 숫자 3과 답의 숫자 2 사이 연결만 확인
- 마지막 답이 2라는 사실로 설명의 3이 올바르게 바뀌는 것은 아님
- 내부 충실성 열은 코드에 숨은 정답이 아니라 관찰 불가능 항목. 계산하지 않고 미측정으로 표시

○ 예시 D를 반례로 추적

```text
reason_count = 3, answer_count = 3
3 != 3 -> False             불일치 없음
3 == reference_count(2) -> False
```

- 같은 오류를 반복하면 서술 일치 점수가 좋아지는 반례
- "불일치가 없으므로 좋은 설명"이라는 보고를 "이 규칙으로 불일치를 찾지 못했으나 정답 기준에는 실패"로 수정할 이유
- 자연어에서 숫자를 추출하는 정확도도 별도 문제. 이번 코드는 의미 분석 없이 제공 숫자를 비교하는 골격

### EU AI Act: 위험을 사용 목적에서 읽기

□ 법률과 수업 체크리스트의 관계

- EU AI Act: Regulation (EU) 2024/1689, AI 사용에 대한 EU 규율
- EU 시장, 사용, 출력의 EU 내 이용 등 적용 범위는 [Article 2](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-2) 별도 검토 필요
- 제주 프로젝트가 자동으로 EU 규제 대상이라는 단정 금지
- 수업 체크리스트: 책임과 위험을 연습하는 도구. 법률 적합성 인증 아님
- 실제 배포 결정: 관할, 용도, 운영 주체, 적용 시점, 관련 법령을 함께 검토

□ 위험 수준을 읽는 기본 지도

| 검토 범주 | 먼저 확인할 질문 | 교육용 행동 |
|---|---|---|
| 금지 관행 | Article 5에 해당하는 사용인지 | 실행하지 않고 해당 조건부터 검토 |
| 고위험 | Article 6와 Annex I/III 용도인지 | 데이터·위험·감독·문서화 조건 검토 |
| 특정 투명성 의무 | 생성·상호작용 등 Article 50 대상인지 | 이용자가 생성·가공 상태를 알 수 있게 설계 |
| 그 외 사용 | 다른 의무·관할·용도 변경이 있는지 | 최소 위험이라는 표현으로 모든 책임을 지우지 않기 |

- Commission의 위험 수준 소개는 이해용 지도. 여러 의무가 함께 적용되는지 별도 조문 확인 필요
- 출처: [Commission AI Act 개요](https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai), [Article 50](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-50)
- 체크리스트에 "등급"만 쓰면 정보 소실. 해당 용도, 의무 후보, 미확인 조건까지 기록할 이유

□ 분류 전 확인할 사용 목적

- intended purpose: 어떤 사람이 어떤 상황에서 결과를 사용하도록 설계했는지

### 차등 프라이버시: 노이즈 크기와 정확도

□ 실습 데이터의 경계

- 공개 제주 문서에서 확인한 행정시 이름을 통계 범주 이름으로 활용
- 20개의 선호 레코드는 교수 작성 상정 자료. 관광객, 주민, 학생의 실제 응답 아님
- 이름, 학번, 연락처, 위치 이력 수집 없음
- 실제 개인자료가 없어도 공개 통계 메커니즘의 가정을 연습할 수 있는 구성
- 제주 관광객 조사 결과나 실제 정책 수용률이라는 해석 금지

□ 인접 데이터와 기여 제한

- 인접 관계: 참여 레코드 하나를 추가하거나 제거한 두 데이터셋(add/remove)
- 질의: 제주시 범주를 선택한 레코드 수 하나만 공개
- 참여자 한 명의 기여: 0 또는 1, 중복 기여가 없다는 상정
- 전역 민감도 Δf: 인접 데이터셋에서 이 count가 변하는 최대값 1
- 여러 방문 기록을 한 사람의 레코드로 바꾸면 기여 제한과 민감도 재설계 필요
- 이번 예시는 사용자 단위 중복 식별이나 실제 데이터 파이프라인 구현 없음


□ 노이즈가 필요한 이유: 정확한 count의 차이

- 작성 데이터 D에서 제주시 count가 12, 한 레코드를 추가한 D'에서 count가 13인 상황
- 두 count를 정확히 공개하면 한 레코드의 차이가 그대로 드러나는 구조
- 이름 제거만으로는 이 차이 문제를 해결할 수 없는 경우 존재
- DP의 질문: 한 사람이 포함되거나 빠져도 어떤 결과가 나올 가능성이 얼마나 달라지는가
- 보호 대상은 데이터 전체의 비밀 유지가 아니라 정의한 인접 관계에서의 참여 기여 차이

□ DP의 확률 조건을 읽는 방법

```text
Pr[M(D) in S] <= exp(epsilon) × Pr[M(D') in S]
D, D': 인접 데이터셋
M: 무작위 공개 메커니즘
S: 관찰할 수 있는 출력 결과의 집합
epsilon: 두 데이터에서 결과 확률이 달라질 수 있는 상한 매개변수
```

- 이 부등식은 모든 인접 쌍과 결과 집합에 대한 조건. 특정 출력 하나에 대한 "안전" 점수 아님
- epsilon 1에서 확률비 상한 exp(1), epsilon 0.5에서 exp(0.5). 후자가 두 분포 차이를 더 제한
- 데이터가 달라도 항상 같은 출력이라는 조건은 아님. 무작위 결과의 분포 비교
- 어떤 개인의 모든 사실을 숨기거나 공개 통계의 유용한 패턴을 없앤다는 뜻은 아님

□ Laplace 메커니즘

- 출력: count + Laplace(0, b)
- 이상적인 연속분포에서 scale b = Δf / epsilon이면 epsilon-DP
- 작은 epsilon: 더 강한 프라이버시 제약, 큰 노이즈 scale
- 큰 epsilon: 더 느슨한 프라이버시 제약, 작은 노이즈 scale
- 근거: [Dwork와 Roth 3.3절](https://www.cis.upenn.edu/~aaroth/Papers/privacybook.pdf)

○ 왜 scale에 민감도가 들어가는가

```text
Laplace density at t: p(t) = exp(-abs(t) / b) / (2b)
M(D) = f(D) + noise
출력 y의 두 density 비율 <= exp(abs(f(D) - f(D')) / b)
abs(f(D) - f(D')) <= Δf
따라서 density 비율 <= exp(Δf / b)
b = Δf / epsilon -> exp(epsilon)
```

- b: 분포가 퍼지는 크기, f(D): 공개할 count, Δf: 인접 쌍의 최대 count 차이
- 앞의 1/(2b)는 같은 b를 사용하는 두 분포의 비율에서 상쇄
- 절댓값의 삼각부등식으로 count 차이가 확률비 상한을 정하는 구조
- 한 사람의 기여를 10회까지 허용하면 Δf를 1로 놓을 근거가 사라지는 이유
- 이번 예시는 공개 질의 count 하나. 두 범주의 벡터나 평균으로 바꾸면 민감도를 다시 계산할 필요

○ 손으로 scale 1과 3 비교

| 설정 | Δf | 기준 epsilon | multiplier | b | 유효 epsilon | 이론 E(abs(noise)) |
|---|---|---|---|---|---|---|
| 기준 | 1 | 1 | 1 | 1 | 1 | 1 |
| 노이즈 증가 | 1 | 1 | 3 | 3 | 1/3 | 3 |
| 노이즈 감소 | 1 | 1 | 0.5 | 0.5 | 2 | 0.5 |

- multiplier 3: 노이즈 평균 절댓값 세 배, 확률비 허용 상한은 더 작은 유효 epsilon에 대응
- 미리 예상할 것: clipping 전 평균 절대 오차 증가, 유효 epsilon 감소
- 표의 평균 절댓값은 이론값. seed 표본 평균과 같은 숫자라고 쓰지 않기

○ 한 표본을 확대하는 교육용 계산

```text
참 count = 12, 표준 Laplace 표본 z = -0.8 (설명용 선택 값)
b = 1: noise = -0.8, 공개 예시 = 11.2, 절대 오차 = 0.8
b = 3: noise = -2.4, 공개 예시 = 9.6, 절대 오차 = 2.4
```

- z=-0.8은 설명용 값. 노트북에서 실제 추출한 표본이라는 주장 없음
- 같은 z를 쓰면 절대 오차가 scale 비율에 따라 변화
- 서로 다른 독립 표본을 한 번씩 뽑을 때에는 큰 scale의 한 출력이 우연히 더 정확할 수 있는 차이
- 전체 분포의 평균적 관계와 출력 한 번의 오차 순서를 구분할 필요

□ 이번 주 한 지점 변경

- 기준 epsilon: 1, 민감도: 1
- 유일한 TODO: `NOISE_MULTIPLIER = 1.0`의 숫자를 `2.0`으로 변경
- scale = multiplier × Δf / 기준 epsilon
- 이상적인 메커니즘의 유효 epsilon = 기준 epsilon / multiplier
- multiplier를 2로 바꾸면 scale 2, 유효 epsilon 0.5
- multiplier를 0.5로 줄이면 유효 epsilon 2. "epsilon 1 보장 유지"라는 표현 금지
- 노트북은 양의 유한한 multiplier만 허용. 함수 작성이나 빈 코드 채우기 없음

- 관찰 질문: multiplier를 세 배로 늘리면 scale과 유효 epsilon이 각각 어느 방향으로 변하는지 예상

□ 재현성과 실제 보장의 분리

- 교육용 고정 seed: 같은 예제의 오차 변화를 비교하는 장치
- 공개된 고정 seed로 실제 민감한 통계를 배포하면 노이즈를 예측·제거할 수 있는 문제
- 노트북 출력은 **DP 보장된 실제 공개 서비스가 아님**
- 실운영은 비공개 난수, 안전한 수치 구현, 기여 제한, 접근 통제, 공개 예산 관리가 필요
- 일반적인 부동소수점 난수 예제를 법률상 익명화 인증으로 취급하지 않기

□ 반복 공개와 사후 처리

- 같은 민감한 데이터에 독립적인 epsilon-DP 질의를 k회 공개하면 기본 순차 합성 상한 k × epsilon
- 여러 노이즈 출력의 평균을 공개하는 것도 추가 예산을 고려해야 하는 공개
- 이번 2,000회 반복: 상정 데이터에서 오차 분포를 관찰하기 위한 계산. 실제 개인 통계 공개 예산 아님
- 음수 count를 0으로 바꾸는 등 DP 출력만 사용하는 clipping은 사후 처리
- 알려진 공개 상한이 있으면 그 범위로 자르는 것도 가능
- 비공개 원자료에서 얻은 상한을 별도로 공개하면 그 공개도 검토 필요
- 근거: [Dwork와 Roth 2.3·3.5절](https://www.cis.upenn.edu/~aaroth/Papers/privacybook.pdf)

□ 정확도 표 해석

- 이번 count의 참값: 상정 레코드 중 제주시 범주의 수
- 출력 표: 기준 scale과 변경 scale, 유효 epsilon, 평균 절대 오차, 음수 출력 비율
- 같은 표준 Laplace 표본을 양의 scale로 늘려 비교하는 공통 난수 실험
- clipping 전 평균 절대 오차는 scale에 비례하는 구성
- 실제 매번의 노이즈 답변이 정확도 순서를 보장하는 것은 아님
- 기댓값과 한 번의 관찰, 교육 표본과 운영 평가의 구분 필요

### 설계도 §선: 정답이 구성 대상인 지역 정책

□ 정책 수용성과 사실 확인의 차이

- 행정시 이름: 출처로 확인 가능한 사실 질문
- 지역 정책의 환경 영향과 수용성: 목표, 비용, 분배, 이해관계가 함께 들어가는 판단
- 공개 문서 요약으로 주민 동의나 정책 정당성을 자동 추론할 수 없는 한계
- 편리한 관광, 환경 보전, 생활권 영향의 가중치 자체가 논의 대상
- 실제 주민 의견이나 도내 기업 자료를 확보했다는 가정 금지

□ 제공된 §선 예시 문장

- **허용**: "시스템은 제주 공개 문서의 출처와 기준 시점을 표시하며 정책 선택지와 확인할 쟁점을 정리한다."
- **보류**: "시스템은 환경 수용성, 주민 동의, 안전, 자격, 권리에 관한 최종 판정을 자동 확정하지 않는다."
- **확인**: "영향을 받는 당사자와 담당자가 근거, 빠진 관점, 이의 제기를 검토한 뒤 판단한다."
- **수정**: "출처 누락, 최신성 미확인, 근거 충돌이 있으면 결과를 보류하고 담당 검토자에게 전달한다."
- **프라이버시**: "개인자료 수집을 최소화하고 집계 공개가 필요하면 기여 제한과 공개 예산을 먼저 정한다."

## 자주 하는 오해 Q&A

<details>
<summary>Q1. 정답과 설명이 맞으면 내부 충실성도 높은가?</summary>

- 두 출력의 정확성만 확인한 상태. 내부 충실성은 별도 근거가 필요한 미측정 항목
- 예시 A는 공개 사실과 일치하는 작성 문장이지만 이 텍스트를 만든 내부 계산의 기록은 없음
- "충실성이 낮다"와 "충실성을 측정하지 않았다"도 다른 결론

</details>

<details>
<summary>Q2. 설명 숫자와 답 숫자가 같으면 프록시 통과인가?</summary>

- 이 좁은 불일치 규칙에서는 통과. 둘 다 틀린 예시 D도 통과하므로 정답·충실성 보장 불가
- D에서 3 != 3은 거짓, 3 == 2도 거짓. 서로 다른 비교의 결과
- 보고에는 검사 규칙과 못 보는 항목을 함께 명시

</details>

<details>
<summary>Q3. 설명을 지우거나 바꾸는 실험만 하면 원인을 알 수 있는가?</summary>

- 개입 설계, 교란, 모델 상태, 과제 범위를 함께 검토할 필요. 이번 실습은 그런 인과 실험 아님
- 생성된 설명을 바꾸면 다음 출력에 영향을 줄 수 있지만, 최초의 내부 계산을 그대로 관찰했다는 뜻은 아님
- 논문 읽기에서 개입한 변수와 관찰한 결과를 분리할 이유

</details>

<details>
<summary>Q4. epsilon을 키우면 더 보호되는가?</summary>

- 이 메커니즘에서는 반대. 같은 민감도에서 epsilon 증가 시 scale 감소, 프라이버시 제약 완화
- Δf=1에서 epsilon 1이면 b=1, epsilon 2이면 b=0.5
- 노이즈 숫자를 줄여 정확도를 높일 때 보호 매개변수도 함께 바뀐다는 해석

</details>

<details>
<summary>Q5. seed를 숨기면 이 노트북을 실제 서비스로 써도 되는가?</summary>

- seed 하나만으로 운영 보장 불충분. 안전한 난수·수치 구현, 기여 제한, 예산, 접근 통제의 별도 설계 필요
- 실제 한 사람이 10개 레코드를 남겼는데 1개로 가정하면 민감도 계산부터 오류
- 여러 답변을 계속 공개하면 단일 질의 epsilon만 보고할 수 없는 문제

</details>

<details>
<summary>Q6. 사람이 승인하므로 고위험이 아닌가?</summary>

- 사용 목적과 결정 영향, 예외의 구체적 조건 검토 필요. 승인 버튼만으로 분류 확정 불가
- 검토자가 원자료를 볼 수 없고 거부·중단 권한도 없다면 실질적 감독의 근거 부족
- 고위험 여부와 감독을 잘 설계했는지는 별도 판단

</details>

<details>
<summary>Q7. 관광 정책의 좋은 답을 정답 문자열로만 평가하면 되는가?</summary>

- 사실 확인과 가치 판단의 구분 필요. 영향을 받는 당사자의 관점과 합의 절차도 평가 대상
- 공개 문서에 정책의 장점이 있다는 사실이 주민 모두의 동의라는 근거가 되지는 않는 구조
- §선에 누구의 어떤 판단을 보류하는지 남기는 이유

</details>
