| 용어 | 이 주차의 의미 |
|---|---|
| RAG | 외부 근거를 검색해 생성 모델의 입력에 연결하는 구조 |
| 색인 | 문서 특징과 문단 ID를 검색 가능한 형태로 보관한 결과 |
| 희소 검색 | 단어·문자 특징의 겹침을 사용하는 검색 |
| 밀집 검색 | 학습된 벡터의 유사도를 사용하는 검색 |
| 재순위 | 이미 확보한 후보의 관련성을 다시 비교하는 단계 |
| 문맥 예산 | 생성 모델에 전달할 근거의 길이 제한 |

| 그래프 확장 | 출처가 있는 개체·관계를 따라 연결 문서를 찾는 과정 |
| Hit@k | 상위 k개 안에 정답 근거가 하나라도 있는 질문의 비율 |
| MRR | 질문별 첫 정답 근거 순위의 역수를 평균한 값 |

## 온라인 (2시수)

### 강의 1: RAG의 구조와 오류 전파

□ 가중치 안의 지식과 문서 안의 지식

- 모델 가중치: 학습 과정에서 압축한 패턴, 답변마다 지식의 출처를 분리하기 어려운 구조
- 외부 문서: 출처, 판 번호, 갱신 시점을 붙여 교체 가능한 근거 저장소
- RAG: 질문과 관련된 외부 근거를 검색해 생성 모델의 입력에 연결하는 방법
- 문서를 찾는 과정과 답변을 만드는 과정의 책임 분리
- 검색 근거가 있다고 해서 답변의 모든 문장이 그 근거에서 나온다는 보장은 없음

○ 원 논문과 수업 골격의 차이

- RAG 논문: 학습된 밀집 검색기와 생성 모델을 결합하는 모델링·학습 방법 제시
- 수업: 고정된 작은 문서에 TF-IDF 색인을 만들고 생성 모델을 그대로 사용
- 실습의 목적: 검색 방식 변경이 후보와 문맥, 답변에 전파되는 경로 관찰
- 원 논문의 학습 목적함수나 성능 재현을 주장하지 않는 범위

□ 색인 시점과 질문 시점

| 시점 | 처리 | 보존할 것 |
|---|---|---|
| 색인 구축 | 수집, 정리, 문단 분할, 벡터 계산 | 원문 URL, 판 번호, 문단 ID |
| 질문 처리 | 질의 벡터, 후보 검색, 재순위 | 후보 순서와 점수 |
| 문맥 구성 | 예산 내 근거 선택 | 실제 입력된 근거 ID |
| 생성 | 질문과 근거를 입력, 짧은 답변 출력 | 답변 원문, 모델 설정 |
| 평가 | 근거·답변 확인 | 실패 유형과 판정 이유 |

- 한 번 만든 색인을 여러 질문에서 재사용하는 구조
- 문서 수정 뒤 색인을 갱신하지 않으면 오래된 근거가 계속 검색될 가능성
- 질문 로그에 원문 전체 대신 문단 ID를 기록해 비교 가능성 확보

□ 오류가 뒤 단계로 전달되는 경로

- 원문에 답이 없음 → 어떤 검색기로도 근거 생성 불가
- 원문에 답이 있으나 후보에 없음 → 재순위가 복구할 범위 밖
- 후보에 답이 있으나 문맥 예산에서 잘림 → 생성 모델이 근거를 받지 못한 상태
- 모델이 근거를 받았으나 질문 조건 무시 → 검색 성공과 최종 답 실패의 공존
- 모델이 맞는 답을 냈으나 근거가 뒷받침하지 않음 → 우연한 정답과 근거 기반 답변의 구분

### 강의 2: 검색 방법과 재순위

□ 단어 TF-IDF

- TF: 문서 안 단어의 빈도
- IDF: 많은 문서에 나오는 단어보다 드문 단어에 더 큰 가중치 부여
- 질의와 문서를 같은 단어 좌표계에 올려 유사도 비교
- 간단한 출발점과 CPU 실행의 장점
- 조사·띄어쓰기·활용형이 달라지면 같은 개념이 다른 토큰으로 분리되는 한계

○ 한 질문으로 보는 토큰화

- "한라산"과 "한라산의"는 단어 토큰 기준에서 서로 다른 항목 가능
- 문자 n-gram은 "한라", "라산" 같은 부분 문자열 공유 가능
- 부분 문자열 공유가 곧 의미 일치나 정답 근거를 뜻하지 않는 점
- 노트북에서 같은 질의의 두 점수를 비교하되 점수의 숫자를 모델 간 확률처럼 비교 금지

□ 문자 TF-IDF

- 문자 단위 연속 부분 문자열로 문서 표현
- 한국어 조사·표기 차이에 일부 대응 가능
- 의미가 다른 단어 사이의 부분 겹침으로 오탐 발생 가능
- n-gram 범위 확대 시 특징 수와 색인 크기의 증가
- 작은 색인의 실험은 단어/문자 방식 비교부터 시작하는 범위

□ 밀집 검색

- 질문과 문단을 학습된 인코더의 벡터로 변환
- 단어가 정확히 같지 않아도 관련 의미를 찾는 목표
- DPR 논문: 질문 인코더와 문단 인코더를 나눠 계산하는 이중 인코더 구조
- 문단 벡터를 미리 계산해 질의 시 비교하는 구조
- 도메인·언어·질의 유형에 맞는 평가 없이는 희소 검색보다 우수하다고 단정 불가

□ 재순위의 역할

- 1차 검색: 전체 색인에서 적은 수의 후보 확보
- 재순위: 확보한 후보의 관련성을 더 자세히 비교해 순서 수정
- 수업 골격: 질의 토큰의 문단 내 포함 비율로 후보 재정렬
- 질의·문단을 함께 읽는 학습된 cross-encoder와 구별하는 단순 기준선
- 후보가 아예 없으면 재순위로 추가 문서 발견 불가

○ 재순위에 확인할 세 가지

- 후보 수: 정답 문서가 후보에 포함될 여지
- 재순위 기준: 질문의 핵심 조건을 반영하는 정도
- 문맥 예산: 최종 모델에 전달할 근거의 크기
- 후보 수를 늘릴 때 검색 시간, 후보 품질, 문맥 전달의 동시 확인

□ 검색 방법만 바꾸는 비교

- 같은 문서, 같은 질문, 같은 후보 수, 같은 재순위와 모델 유지
- 바꿀 대상: `retrieve_word` → `retrieve_char` 함수 선택 한 곳
- 비교 대상: 후보 ID, 근거 문장, 짧은 생성 답변, 실패 분류
- 생성은 greedy decoding으로 실행해 샘플링 변수를 줄이는 설정
- 환경이 달라질 때 실행 시간은 달라지므로 절대 시간의 일반화 금지

### 강의 3: 검색 평가와 답변 평가

□ 정답 문서의 정의부터 확인

- 질문이 요구하는 사실을 직접 뒷받침하는 문단의 수동 판정
- 지명만 포함하는 문단을 정답 문서로 삼지 않는 원칙
- 질문이 "어디에 있는가"인데 역사만 설명하는 문단은 주제 관련 문서
- 여러 문단이 필요한 질문은 정답 근거 집합으로 표현
- 원문에 답이 없는 질문은 빈 근거 집합과 함께 기록

□ 최소 검색 지표

- Hit@k: 정답 근거 중 하나라도 검색된 질문의 비율
- Recall@k: 질문별 전체 정답 근거 중 검색된 비율
- MRR: 첫 정답 근거의 순위 역수, 없으면 0
- 정답 근거가 여러 개인 경우 Hit과 Recall의 차이 확인
- 본 노트북의 자동 체크는 문자열 포함 문단 집합에 대한 예비 Hit@k
- 예비 Hit@k를 사람이 확인한 검색 정확도로 보고하지 않는 원칙

○ 손으로 계산하는 예시

- 설명용 질문 3개, 첫 정답 순위가 1, 3, 없음인 상황
- Hit@3 = 2 / 3
- MRR = (1 + 1 / 3 + 0) / 3 = 4 / 9
- 실제 제주 실습의 측정값이 아닌 계산 연습

□ 최종 답변 지표

| 확인 항목 | 질문 |
|---|---|
| 답의 정확성 | 질문 조건에 맞는 사실인가 |
| 근거 충실성 | 답의 각 사실을 전달된 문맥이 지지하는가 |
| 인용 일치 | 표기한 문단 ID가 실제 근거인가 |
| 유보 적절성 | 원문에 답이 없으면 부족함을 드러내는가 |
| 실행 비용 | 입력 길이와 후보 수가 감당 가능한가 |

- 맞는 답과 올바른 인용의 별도 판정
- 근거가 있어도 생성 모델의 출력이 틀릴 수 있는 상황
- 근거가 없는 답을 유창하게 생성하면 검색 성공으로 인정하지 않는 원칙
- 두 방법의 승패보다 실패가 바뀐 이유를 설명하는 목표

□ 7주차 장문맥과의 연결

- Lost in the Middle: 연구에서 관련 정보의 위치에 따라 성능 변화 관찰
- 검색 후보를 더 많이 넣는 선택이 항상 유리하지 않은 근거
- 필요한 근거를 앞에 놓는 것과 사실상 필요 없는 문서를 삭제하는 것의 구분
- 수업의 작은 생성 예제로 장문맥 현상 전체를 재현했다고 주장하지 않는 범위

### 그래프 기반 검색 확장의 아이디어와 한계

□ 문단 검색이 놓치는 질문

- 여러 문서에 흩어진 개체·관계를 연결하는 다중 홉 질문
- 한 문단보다 문서 집합의 공통 주제를 요구하는 질문
- 단어 겹침이 작아도 개체 관계가 질문을 이어 주는 경우
- 연결이 필요한지 먼저 판정한 뒤 그래프 도입을 검토하는 순서

□ 그래프 확장의 기본 골격

- 노드: 개체 또는 문서
- 간선: 원문에 근거가 있는 관계 또는 연결
- 시작점: 질문의 개체와 1차 검색 문서
- 확장: 이웃 개체와 연결 문서 탐색
- 재검증: 연결된 문서가 질문 조건을 만족하는지 원문 확인

○ 관계를 만들 때의 위험

- 같은 이름을 가진 서로 다른 개체를 합치는 오류
- 한 개체의 약칭·다른 표기를 다른 노드로 나누는 오류
- 같은 문장에 등장했을 뿐인 두 개체를 인과 관계로 해석하는 오류
- 과거 관계를 현재 관계로 사용하는 오류
- 추출 모델이 만들어 낸 간선의 원문 근거 누락

□ GraphRAG 논문의 범위

- Edge et al.: 개체 그래프에서 커뮤니티와 요약을 구성하는 접근
- 문서 집합 전체의 주제를 묻는 질문 중심의 설계
- 모든 RAG에 그래프를 의무적으로 붙인다는 주장과 구별
- 개체 추출·요약의 사전 처리와 갱신 비용 고려
- 수업의 개념도는 논문 구현이나 성능을 재현한 그래프가 아님

□ 토론: 먼저 무엇을 고칠 것인가

- 조건 A: 원문에 정답 문단이 있지만 단어 검색에서 후보 누락
  - 토큰화·문자 검색·질의 표현부터 확인
- 조건 B: 후보에는 정답이 있지만 생성 입력에서 잘림
  - 재순위와 문맥 예산부터 확인
- 조건 C: 여러 문서에 근거가 나뉘어 있고 질문이 관계 연결을 요구
  - 그래프 또는 단계별 검색 검토
- 조건 D: 원문에 운영 시간이 없음
  - 추가 공개 출처 수집 또는 답변 유보. 그래프로 사실 생성 불가

□ 데이터 선택 전 확인

- [제주 관광 빅데이터 서비스 플랫폼](https://data.ijto.or.kr): 공개 다운로드 가능 여부와 파일의 내용 확인
- 2026-10-11 작성 환경 확인: 제주데이터허브 초기 페이지 HTTP 200, 관광 플랫폼은 인증서 검증 실패로 다운로드 미확인
- 위 확인은 데이터셋 실물 확보나 두 포털 전체 장애의 증거가 아님
- 선택할 데이터셋의 실제 파일·필드·이용 조건은 수업 시작 전 교수자 확인 대상
- 접근 문제가 있으면 URL과 오류를 기록하고 제공된 위키백과 기준선 실습 진행. 이를 두 포털 데이터 과제 완수로 보고하지 않는 원칙

○ 준비된 골격의 재사용

- 다운로드한 공개 표의 설명·명칭·위치 필드를 문서로 연결하는 어댑터만 교수가 제공
- 학생은 기존 검색 함수 선택 한 곳만 변경
- 표의 숫자 필드는 단위·기간을 함께 문서에 포함하는 조건
- API 키가 필요한 경우 공개 제출물에 키를 포함하지 않는 원칙
- 데이터 원본을 저장소에 커밋하지 않고 출처·수집 시각·파일 해시 기록

□ 3단계 부분점수

- 1단계: 골격 실행, 실제 출처와 접근 상태, 기준선 산출물 제시
- 2단계: 검색 방법 한 곳 교체, 같은 질문과 설정으로 전후 비교
- 3단계: 실패 유형과 원인, 개선안의 검증 방법 제시
- 과제 전체 데이터 요건 충족 여부와 부분 실행 결과의 구분
- 정확한 배점과 제출 경로는 별도 과제 공지 기준

## 스스로 점검

- 후보에 없는 근거를 재순위로 복구할 수 없는 이유 설명
- 단어 TF-IDF와 문자 TF-IDF가 다른 문서를 찾는 조건 제시
- 검색 성공, 문맥 전달 성공, 답변 성공을 각각 판정
- 지명 포함 여부를 정답 근거 판정으로 대신할 수 없는 이유 설명
- 그래프 간선 하나의 근거와 유효 기간을 기록할 방법 제시
- 원문에 없는 답을 만드는 것과 연결된 원문을 찾는 것의 차이 설명

□ 점검 정답

1. 재순위의 입력이 검색 후보뿐이므로 후보 밖 근거를 추가할 수 없는 구조
2. 조사·띄어쓰기·활용형이 달라 단어는 다르지만 문자 부분 문자열이 겹치는 경우. 부분 겹침에 따른 오탐도 가능
3. 검색 성공은 정답 근거의 후보 포함, 전달 성공은 실제 모델 입력 포함, 답변 성공은 질문 조건을 만족하는 정확한 답으로 각각 판정
4. 지명 포함은 주제 관련성의 단서일 뿐 질문이 요구한 높이·위치·기간 등을 직접 뒷받침하는 근거가 아닐 수 있음
5. 간선별 원문 URL·판 번호·문단 ID와 관계의 기준 시점 기록, 현재 유효성은 최신 출처로 재확인
6. 연결 검색은 기존 원문의 사실을 찾는 과정. 원문에 없는 답 생성은 확인 가능한 근거를 새로 확보한 것과 다른 행위

## 자주 하는 오해 Q&A

□ "RAG를 쓰면 환각이 없어지는가"

- 외부 근거를 연결하는 구조일 뿐 오류 제거 보장은 없음
- 검색 실패, 오래된 원문, 잘못된 문맥 사용을 나눠 확인하는 필요

□ "검색 점수가 높으면 정답인가"

- 점수는 검색 표현의 유사도, 질문 조건과 사실성의 확률이 아님
- 서로 다른 검색기의 점수를 같은 척도로 직접 비교할 수 없는 점

□ "k를 늘리면 무조건 좋아지는가"

- 정답 후보 포함 가능성과 잡음·입력 예산의 동시 증가 가능
- 후보 수와 실제 전달한 근거 수를 따로 기록하는 필요

□ "문자 검색이 밀집 검색인가"

- 문자 TF-IDF도 문자 특징에 기반한 희소 표현
- 학습된 문장 벡터를 사용하는 밀집 검색과 구별

□ "그래프가 생기면 관계가 참인가"

- 간선은 추출 결과, 원문과 개체 판정의 검증 필요
- 관계가 연결되어 있어도 질문의 시간·조건을 만족하지 않을 가능성
