### 강의: 최신 논문의 결론을 적용 조건으로 바꾸기

□ 왜 제목과 요약만 읽으면 부족한가

- "에이전트를 늘렸더니 성능 향상"이라는 문장만 남으면 모델·문맥·호출 예산도 함께 바뀌었는지 확인 불가
- 같은 과제라도 평가가 정답 일치인지, 테스트 통과인지, 사람 선호인지에 따라 높은 점수의 의미 차이
- 읽기 순서: 질문 → 주장 → 비교 대상 → 실제 조작 변수 → 측정 → 적용 불가 조건
- 프로젝트에 옮길 문장: "이 조건에서 이 기준선보다 이 측정이 달라졌으며, 우리 조건에서는 이 부분을 다시 확인할 필요"

□ 최신 사례: 협업의 단위보다 의존 관계

- Yuan 외의 2026년 preprint: 작업 의존 그래프·문맥 분리·조율 비용을 함께 분석
- 근거: 원문 §3의 이상화된 분석, §5의 서로 다른 장기 작업 평가
- 고정된 많은 역할보다 작업 간 정보 의존성을 고려한 분할을 검토하는 연구 방향
- 논문이라는 이유만으로 검증 완료된 운영 표준으로 취급하지 않는 원칙
- 사전 공개 논문, 특정 모델·도구·과제 조건의 결과. 우리 제주 사실 질문 성능으로 대체 불가

□ 서로 다른 두 비용

- 이론상의 문맥 비용: 이미 완성된 작업 궤적과 의존 관계를 알고, 필요한 부분만 분리했을 때의 누적 문맥 부담
- 실제 운영 비용: 분할 예측·역할 지시·요약 전달·재시도·동기화까지 포함한 전체 호출 부담
- 문맥 분리가 불필요한 정보를 줄이더라도 조율 호출이 늘면 전체 입력·출력 토큰 증가 가능
- 따라서 논문의 이상화된 부등식만으로 실제 서비스 비용 감소를 주장할 수 없는 구조
- 근거 위치: 최신 논문 §3.1.3과 §3.2. 이번 노트북은 그 이론·시스템의 구현 재현 아님

□ 정보를 나누기 전에 묻는 질문

### 강의: 제공된 Self-Refine 실험의 원리

□ 왜 답을 다시 생성하기 전에 피드백을 만드는가

- 첫 답에서 누락한 조건을 명시하면 수정 단계가 무엇을 바꿀지 더 분명해질 가능성
- 그러나 검토자도 같은 모델이면 처음의 오해를 반복할 가능성
- 피드백은 정답 라벨이 아니라 또 하나의 생성 결과. "검토했다" 자체를 성공 근거로 삼지 않는 원칙
- 원 논문의 방법: 같은 모델이 초안을 만들고 피드백을 생성한 뒤 이를 이용해 수정
- 근거: Self-Refine §2. 이번 실습은 해당 세 단계 구조를 한 회 제공

□ 세 단계의 정의와 기호

- `x`: 공개 문맥과 질문, `M`: 고정된 모델 가중치
- `p_gen`, `p_fb`, `p_refine`: 교수 제공 생성·피드백·수정 지시
- `y0 = M(p_gen + x)`: 초안
- `fb = M(p_fb + x + y0)`: 근거와 초안을 함께 본 검토
- `y1 = M(p_refine + x + y0 + fb)`: 검토를 참고한 수정
- `+`: 입력 문장의 연결, 숫자 덧셈이나 가중치 학습 연산이 아님
- 실제 노트북에서는 원 논문 few-shot 예제를 옮기지 않고 짧은 한국어 지시 사용. 프롬프트 동일 재현 아님

□ 제주 공개 사실에 연결

- 고정판 행정시 문단을 runtime 수집, 제목·판 번호·행정시 명칭 존재 확인
- 질문 세 개: 두 행정시 이름, 행정시 수, 제주시 외 행정시 이름
- 정답은 공개 근거와 대조한 교수 제공 기준, 모델 피드백에서 정답을 만들어 내지 않는 구조
- 초안 출력은 검토 프롬프트로 전달, 피드백 출력은 수정 프롬프트로 전달
- 직접 생성과 수정 구성의 비교에서 동일 초안을 공유, 시작점 차이를 줄이는 설계
- 모델이 지시를 지키지 않거나 출력이 잘려도 그 응답과 실패를 그대로 기록

- 관찰 질문: 피드백 단계가 참조하는 정답과 학생에게 보여 주는 공개 근거가 같은 정보인지 확인

- 그림 해석: 세 상자는 서로 다른 가중치의 독립 모델이 아님. 같은 가중치의 역할 분리
- 12주차와 연결: 설명·검토 문장이 그럴듯하더라도 사실성과 내부 충실성이 자동으로 확인되지 않는 구조

□ 작은 계산 예제: 호출 예산

- 질문 수 `n=3`, direct는 질문당 1호출, 한 회 refine은 질문당 초안·피드백·수정 3호출
- 각각 운영할 때 direct `3×1=3`호출, refine `3×3=9`호출
- 실습은 초안을 공유하므로 실제 비교용 생성은 9호출. direct 3호출과 refine 9호출을 합쳐 실제 12호출이라고 보고하지 않는 구분
- 예열 1호출은 모델 준비와 비교 측정 분리를 위해 별도 실행, 비교 표에서 제외
- 호출마다 최대 24 생성 토큰이므로 세 단계의 생성 상한은 질문당 72토큰
- EOS 조기 종료에 따라 실제 생성 토큰은 상한보다 작을 수 있음. 토큰 수는 실측 로그에서 읽기

□ 실제 시간이 정확히 3배가 아닌 이유

- 피드백 입력에는 초안이, 수정 입력에는 초안과 피드백이 추가되므로 프리필 부담 변화
- 출력 길이와 EOS 위치, CPU 부하, 라이브러리·메모리 상태의 영향
- 노트북 `generate_sec`: 토큰화 이후 generate 구간의 wall time, 프리필과 디코딩 포함
- 순수 디코딩·사용자 요청 전체 지연·설치 시간을 측정했다고 표기하지 않는 원칙
- 모델 로딩 시간은 별도 기록, 같은 가중치를 공유하는 비교에서 매 호출에 반복 합산하지 않음

□ 결과 읽기: 교정만 세면 놓치는 것

| 초안 판정 | 수정 판정 | 이름 | 확인할 출력 |
|---|---|---|---|
| 일치 | 일치 | 유지 정답 | 근거 없는 추가 주장 여부 |
| 불일치 | 일치 | 교정 | 어떤 피드백이 어떤 변경으로 이어졌는지 |
| 일치 | 불일치 | 퇴행 | 검토가 맞는 답을 망가뜨렸는지 |
| 불일치 | 불일치 | 유지 실패 | 피드백 오류·반영 실패·형식 오류의 구분 |

- 위 판정은 지정한 첫 줄 형식 일치. 모든 의미적 정답과 사실 정확도를 평가한 점수가 아님
- 도시 두 이름은 지정 구분자 제거 후 정확한 두 이름 순서만 인정, 수는 `2`로 표기
- "제주시와 서귀포시가 아니다"처럼 정답 단어를 포함한 부정문을 단순 포함 검색으로 정답 처리하지 않는 이유
- 의미가 맞지만 형식이 다르면 자동 판정은 실패, 출력과 수동 판정을 별도로 보존
- 결과 확인 뒤 채점 규칙을 특정 구성에 유리하게 바꾸지 않는 비교 규율

### 강의: GPU 없는 운영 조건에서 비교하기

□ 경량 배포와 역할 분리는 다른 선택

- 모델 경량화: 가중치·활성 메모리·연산량을 줄이는 접근
- 역할 분리: 프롬프트와 정보 전달을 나누는 접근, 가중치 크기 감소를 보장하지 않음
- 이번 실험: 작은 Base 모델 하나를 CPU에서 공유, 역할 호출은 순차 실행
- 모델 3개를 동시에 메모리에 올린 실험, 독립 전문가 집단, 분산 시스템 실험 아님
- 일반 조직의 RAM·응답 대기 허용치·오류 확인 인력 조건을 먼저 적고 구성 판단

□ 가중치와 전체 메모리 구분

- 파라미터 수 `P`, 파라미터당 바이트 `b`일 때 가중치 바이트 `P×b`
- 작성 산술 예: `P=600,000,000`, float32 `b=4`이면 `2,400,000,000`바이트, 약 `2.24 GiB`
- 이 숫자는 반올림한 교육 계산, 실제 모델 파라미터 수는 노트북 `parameter_count`에서 확인
- 전체 메모리는 가중치 외에 KV 캐시·중간 텐서·토크나이저·프로세스도 포함
- 따라서 2.24 GiB RAM만 있으면 실행된다는 판단 불가
- 저정밀 가중치의 절감 비율만으로 CPU 지연·품질까지 예측 불가. 별도 실험 없으므로 이번 비교에서 양자화 성과 미측정

- 관찰 질문: 비용 표에서 현금 비용과 입력 토큰 비용을 같은 칸에 넣어도 되는지 확인

| 주장(claim) | 저자가 조건과 함께 제시한 결론 | 우리 조건으로 확장한 해석 |
| 근거(evidence) | 결론을 뒷받침하는 방법·측정·대조 | 요약문 자체 |
| 기준선(baseline) | 같은 비교에서 출발점이 되는 구성 | 예산이 다른 결과 |
| 방법 구조 재현 | 논문의 계산·정보 흐름 일부를 제공 코드로 실행 | 전체 성능 재현 |
| 자기 피드백 | 같은 모델이 초안을 검토하는 생성 단계 | 외부 정답·독립 검증 |
| 퇴행(regression) | 처음 일치한 답이 수정 후 불일치 | 개선 수만 세는 평가 |
| 역할 분리 | 프롬프트·정보 전달을 단계별 구분 | 모델 가중치 복제 |
| 의존 관계 | 다음 작업이 앞 정보에 의존하는 구조 | 역할 수 |
| 경량 배포 | 제한된 장비에서 모델 실행 부담을 조정 | 운영 SLA 보장 |
| 대리 지표(proxy) | 토큰·호출 등 직접 목적을 대신 보는 수치 | 현금 비용·전체 품질 |
