## 이번 주차

멀티모달 표현의 결합

□ 이 주차가 놓이는 자리

- 5주차까지 모델은 글자(토큰)만 봤다. 질문도 답도 텍스트였다. 그런데 실제 데이터의 절반가량은 글이 아니다. 사진, 관측 기록의 그림, 센서 캡처가 그 대상이다
- 이번 주는 사진과 글을 **같은 공간에서 비교하는** 모델을 봐야 한다. 핵심 질문은 둘이다
  - 사진과 문장을 어떻게 **하나의 벡터 공간**에 놓는가 (정렬, alignment)
  - 정렬된 모델에 이미지를 넣고 질문하면 **무엇이 가능해지고 무엇이 깨지는가**
- 두 가지 구조를 나란히 본다
  - **쌍둥이 인코더**(dual encoder, CLIP): 이미지와 문장을 각자 벡터로 만들어 비교만 한다. 빠르지만 "문장을 생성"하지는 못한다
  - **인코더+디코더**(VLM, SmolVLM): 이미지 벡터를 언어모형의 입력에 붙여 "문장으로 답"하게 한다. 유연하지만 이미지가 문맥을 잠식한다

□ 이번 주가 답하는 질문

- 사진과 문장의 유사도는 어떻게 계산되는가 (두 인코더가 어디서 만나는가)
- 같은 사진을 두고 텍스트 전용 모델과 멀티모달 모델의 답이 어떻게 다른가
- 이미지가 들어가면 언어모형의 문맥이 어떻게 되는가
- 라벨의 언어가 정렬 공간에 어떤 영향을 주는가 (한국어 라벨의 실측 결과)

□ 사진과 실측에 대하여

- 예제 사진은 위키미디어 공용과 공공누리에서 가져온 제주 공개 사진 5장이다. 출처와 라이선스는 이 문서 아래 [사진 출처] 표에 정리했다
- 본문의 숫자와 답은 이 저장소에서 실행한 실측값이다. 모델은 CLIP(openai/clip-vit-base-patch32), SmolVLM(HuggingFaceTB/SmolVLM-256M-Instruct), 텍스트 전용 모델(Qwen3-0.6B-Base)이다. 실행 환경에 따라 답의 문구나 소수점 자리가 달라질 수 있다
- 도내 기업 데이터는 없다. 기업은 학습활동 [실무]에서 조건 상정으로만 등장한다

## 온라인 (2시수)

### 강의: 사진과 문장을 한 공간에 놓는 두 가지 방법

□ 왜 "비교"와 "생성"이 갈리는가

- 사진을 아는 모델을 만드는 길은 크게 둘이다
  - **비교형**: 사진 벡터와 문장 벡터의 유사도를 계산한다. "이 사진은 이 문장과 얼마나 닮았나"를 재는 자
  - **생성형**: 사진을 언어모형에 넣어 문장을 이어 쓰게 한다. "이 사진에 대해 답하라"를 수행하는 자
- 두 구조는 쓰임이 다르고 깨지는 방식도 다르다. 이번 주는 둘 다 직접 돌려 본다

<ClipFlow />

□ 쌍둥이 인코더(CLIP) - 두 벡터의 코사인 유사도

- CLIP은 이미지 인코더와 텍스트 인코더 **둘을 동시에** 학습시켰다. 학습 목표는 단순하다. 짝이 맞는 (사진, 문장) 쌍의 벡터는 가깝게, 짝이 아닌 쌍은 멀어지게
- 두 인코더의 내부는 전혀 다르다. 이미지는 ViT(사진을 16x16 패치로 잘라 패치 하나를 토큰처럼 본다), 텍스트는 텍스트 트랜스포머다. 그런데 **내보내는 벡터의 차원을 같게**(ViT-B/32는 512차원) 맞춰 두고, 벡터를 **길이 1로 정규화**한 뒤 내적한다. 정규화된 벡터의 내적이 곧 코사인 유사도다
- 질문에 답하는 방법이 독특하다. "분류기 머리(classification head)를 학습"하지 않는다. 후보 문장 여러 개를 텍스트 인코더에 넣고, 사진 벡터와 가장 유사한 문장을 고른다. 이것이 **제로샷 분류**다. 학습 때 본 적 없는 라벨로도 바로 쓸 수 있다
- 확률은 이렇게 나온다

```
cos_sim = 정규화된 이미지 벡터 · 정규화된 문장 벡터
logits  = cos_sim x logit_scale   (ViT-B/32 실측 100.0)
probs   = softmax(logits)
```

- logit_scale은 학습되는 온도 상수다. 실측값이 100.0이라는 뜻은 유사도의 작은 차이(0.26과 0.27)가 확률에서는 큰 차이로 벌어진다는 뜻이다

○ 제로샷 실측 - 라벨의 언어가 결과를 바꾼다

- 제주 공개 사진 5장(성산 일출봉, 주차장, 영실 등산로, 만장굴, 우도)에 제로샷 분류를 돌렸다. 아래 히트맵에서 라벨 조합을 바꿔가며 보라. 행: 사진, 열: 후보 라벨, 가장 진한 칸: 모델이 고른 라벨

<ClipHeatmap />

- 관찰 세 가지다
  - **영어 라벨은 맞춘다**: 짧은 라벨 4/5, 장면 묘사 라벨 5/5. 사진 내용이 라벨에 반영될수록 대각선이 뚜렷해진다
  - **한국어 라벨은 무너진다**: 1/5. 히트맵이 평평해진다. 사진과 한국어 라벨 사이에 방향 차이가 보이지 않는다는 뜻이다
  - **한국어에 영어를 섞으면 부분 회복**: 3/5 (실행 환경에 따라 4/5). 한국어가 그 공간의 좌표가 아니라는 증거이기도 하다
- 원인은 토큰화가 아니라 학습 데이터다. 한국어 라벨을 CLIP의 토크나이저로 잘라 보면 글자가 **바이트 조각으로 분해**된다(예: '성' -> 조각 2개). 그래도 토큰 자체는 만들어진다. 문제는 그 토큰들이 정렬 공간에서 **어디에 놓였는가**다. CLIP의 4억 쌍 학습 데이터는 영어 위주라 한국어 토큰은 사진 방향과 정렬된 적이 거의 없다. 공간은 학습 데이터의 언어에 묶인다
- 운영 교훈은 이렇다. **제로샷의 성능은 모델 크기만으로 정해지지 않는다. 라벨의 언어와 학습 데이터의 겹침이 함께 정한다.** 라벨을 영어로 서거나, 한국어에 영어를 괄호로 붙이는 것이 임시 방법이 된다

□ 인코더+디코더(VLM) - 이미지를 문맥에 붙여 답하게 하기

- 비교형은 "문장을 만들지" 못한다. 질의응답처럼 답이 서술인 과제에는 생성형이 필요하다
- VLM(Vision-Language Model)의 구조는 단순하다. 사진을 이미지 인코더로 벡터로 만들고, 그 벡터들을 **언어모형의 입력 토큰 자리에 끼워 넣는다.** 언어모형은 사진 벡터를 "사진에 대한 토큰들"로 취급해 이어서 문장을 생성한다. 5주차의 LLM judge가 언어모형이던 것과 같은 원리다. 이미지가 붙을 뿐이다
- 이번 주에 쓰는 SmolVLM-256M-Instruct는 2.56억 파라미터의 경량 VLM이다. 노트북 단계에서 확인하게 될 세부는 이렇다
  - 텍스트 백본: llama 계열, 은닉 576, 층 30
  - 비전 백본: SigLIP 계열, 은닉 768, 층 12, 패치 16
  - 사진 1장이 832개의 시각 토큰으로 들어간다(960x640 기준 실측). 질문이 몇 토큰이든 이미지가 문맥의 대부분을 차지한다
- 답의 형태는 채팅 템플릿(chat template)으로 만든다. 모델에 넣기 전에 대화 형식을 프롬프트로 조립하는 절차가 있다는 점이 4주차의 프롬프트 설계와 이어진다

○ 실측 대조 - 텍스트 전용 모델에게 사진을 물으면

- 텍스트 전용 모델(Qwen3-0.6B-Base)에게 "이 사진에는 무엇이 보이나요?"를 물었다. 사진은 줄 수 없으니 **모델이 문맥을 지어낸다**

| 모델 | 질문 | 답 (실측) |
|---|---|---|
| 텍스트 전용 (Qwen3-0.6B-Base) | What is in this photo? | "A man is standing in front of a building. ... white shirt ... black hat ... umbrella" |
| 텍스트 전용 (Qwen3-0.6B-Base) | 사진 속에 나무가 몇 그루인가? | "3 그루입니다. 나무는 3 그루입니다. ..." (같은 문장 반복) |
| 멀티모달 (SmolVLM-256M) | 같은 질문, 성산 일출봉 사진 | "the water, rocks, hill and the sky" |

- 텍스트 전용 모델의 답은 두 성격으로 나뉜다
  - 언어적 그럴듯함이 높다. 문장이 자연스럽고, 형식도 갖춰 있다
  - 그러나 **사진을 본 적이 없으므로 전부 지어낸 것이다.** 나무 세 그루라는 답도, 흰 셔츠라는 답도 근거가 없다
- 5주차의 false acceptance와 같은 뿌리다. **다음 토큰 확률 기계는 "그럴듯한 것"을 낼 뿐 "참인 것"을 보장하지 않는다.** 다만 VLM은 사진이 문맥에 들어가므로 지어낼 여지가 구조적으로 줄어든다. 답이 사진을 따라 움직인다

○ 실측 대조 - 이미지를 바꾸면 답이 따라 움직인다

- SmolVLM에 같은 질문("Describe this image in one sentence.")을 주고 사진만 다섯 장으로 바꿔 봤다

| 사진 | 답 (실측) |
|---|---|
| 성산 일출봉 | "the water, rocks, hill and the sky" |
| 성산 주차장 | "a few vehicles on the road, ... people standing, ... trees, ... a mountain" |
| 영실 등산로 | "a bridge, railing, trees, hills, clouds and the sky" |
| 만장굴 | "a black color object" (어둡고 세부가 적어 답이 무너진다) |
| 우도 해안 | "the sea, rocks, hills, trees, buildings, and the sky" |

- 질문은 고정이고 사진만 바뀌었는데 답이 사진 내용을 따라 바뀐다. **멀티모달 모델의 답은 이미지에 근거(grounded) 있다**는 것의 실측 형태다. 학습활동 [구현]이 이 실험의 연습판이다
- 같은 실험의 어두운 면도 본다. 만장굴은 답이 "a black color object"로 무너진다. **이미지가 어둡고 특징이 적으면 근거는 있어도 답의 질이 떨어진다.** 근거가 있다는 것과 답이 좋다는 것은 다르다

○ 실측 대조 - 한국어 질문은 어떻게 깨지는가

- SmolVLM에 한국어 질문을 넣으면 대부분 실패한다

| 한국어 질문 | 답 (실측) |
|---|---|
| 이 이미지를 한 문장으로 묘사하라. | 질문을 그대로 되풀이 (성산 주차장 사진) |
| 여기가 어디인가? 주된 피사체가 무엇인가? | "어디에서 이미지를 입력하시고 있습니다" (깨진 한글) |
| (같은 질문, 영실 사진) | "어디에서 이미지를 제공하지만 이미지..." (깨진 한글) |

- 흥미로운 예외도 있다. 같은 한국어 질문("이 이미지를 한 문장으로 묘사하라.")에 영실 사진에서는 **영어 답**("This is a wooden pathway that is long and wide.")이 나온다. 질문의 언어가 아닌 **모델이 답을 내는 언어**가 문제라는 뜻이다
- 원인은 CLIP과 같은 방향이다. 학습 데이터의 언어 분포다. 256M 모델의 지시 학습 데이터는 영어 위주라 한국어 지시의 다음 토큰 확률이 무너진다. **모델 크기의 문제가 아니라 데이터 분포의 문제**라는 점이 5주차의 "지표가 놓치는 것"과 같은 사고방식이다

□ 이미지가 문맥을 잠식한다 - 832 토큰의 의미

- 사진 1장이 832개의 시각 토큰을 쓴다(960x640 실측). 이것의 의미를 7주차(장문맥)를 미리 보며 잡아 둔다
  - 질문이 10토큰이어도 문맥은 842토큰이다. **이미지가 문맥 창의 대부분을 차지한다**
  - 문맥 창이 작은 모델일수록 사진 몇 장으로 한도가 온다
  - 사진을 더 크게 넣을수록(해상도를 올릴수록) 시각 토큰이 늘어난다. 지연·비용이 여기서 온다
- 학습활동 [실무]의 지연·비용 보고가 이 관찰을 근거로 한다

### 학습활동

- 텍스트 전용 모델(Qwen3-0.6B-Base 같은 작은 모델)과 멀티모달 모델(SmolVLM)에 **같은 질문**을 준다. 질문은 사진을 보고 답해야 하는 것이어야 한다(예: "이 사진에는 무엇이 있나요?", "사진 속 하늘 상태는 어떤가?")
- 텍스트 전용 모델의 답과 멀티모달 모델의 답을 나란히 놓고 **답이 사진을 따라 바뀌는지**를 기록한다. 텍스트 전용 모델의 답은 사진 없이도 얼마든지 나오므로, "그럴듯하지만 근거가 없다"가 실측으로 드러나는지 확인한다
- 한국어 질문과 영어 질문을 각각 넣어 **답의 언어와 질이 어떻게 달라지는지**도 함께 기록한다

## 대면 (1시수)

### 경량 멀티모달 모델 동작 분석 - 두 구조의 깨지는 지점을 직접 읽는다

□ 분석 관점 - 어디가 깨졌는가를 세 층으로 나눠 본다

- 온라인의 실측 결과를 대면에서 세 층으로 분해한다

| 층 | 보는 것 | 실측 예 |
|---|---|---|
| 입력 표현 | 사진이 몇 개의 시각 토큰이 되는가, 해상도와 토큰 수의 관계 | 960x640 -> 832 토큰 |
| 정렬 공간 | 라벨 언어와 제로샷 정확도의 관계 | 영어 5/5, 한국어 1/5 |
| 생성 언어 | 질문 언어와 답의 언어·질의 관계 | 한국어 질문 -> 영어 답 또는 깨진 한글 |

- 세 층 모두 "모델이 나쁘다"가 아니라 **"어느 층에서 어떻게 깨지는가"** 를 찾는 것이다. 깨진 층을 못 박아야 개선 방법이 정해진다

○ 층별 분석 연습 - 실측 기록을 근거로 쓰는 훈련

- 분석 기록의 형식은 5주차 Q4 근거 기준을 이어받는다. 예시는 이렇다

```text
관찰: 한국어 라벨로 제로샷 분류했더니 5장 중 1장만 맞았다.
     히트맵이 평평해져 사진별 차이가 거의 없었다.
근거: CLIP ViT-B/32, 제주 공개 사진 5장, 라벨 "OO 사진" 형식 5개,
     노트북 1-4 실측 (cos_sim 표와 softmax 확률 포함)
해석: 토큰은 만들어진다(BPE 조각). 그러나 학습 데이터가 영어 위주라
     한국어 토큰이 사진 방향과 정렬된 적이 없다.
     -> 모델 결함이 아니라 정렬 공간의 언어 편향
다음: 라벨을 영어로 바꿔 같은 실험을 다시 돌린다 (실측 5/5).
     한국어 + 영어 괄호 형식으로 3/5 (실행에 따라 4/5)를 확인한다.
```

- 관찰 - 근거 - 해석 - 다음의 네 칸을 비우지 않는다. 이 형식이 과제 2의 보고 뼈대다

□ 두 구조의 선택 기준 - 비교형과 생성형은 언제 갈리는가

- 운영에서 모델을 고를 때의 기준을 두 구조로 나눠 정리한다

| 기준 | 쌍둥이 인코더 (CLIP) | 인코더+디코더 (VLM) |
|---|---|---|
| 답의 형태 | 라벨이나 순위 (비교) | 자유 서술 (생성) |
| 속도 | 문장 후보를 미리 인코딩해 두면 매우 빠르다 | 이미지마다 생성 시간이 든다 |
| 문맥 비용 | 이미지 1장당 벡터 1개 | 이미지 1장당 수백 토큰 |
| 실패 모양 | 정렬이 안 된 라벨에서 무음 (히트맵 평평) | 그럴듯한 오답, 반복, 깨진 언어 |
| 잘 맞는 일 | 검색, 필터링, 자동 분류 | 질의응답, 설명 생성, 안내 |

- 같은 입력(사진+질문)이라도 요구가 "분류"면 CLIP 쪽이 싸고 빠르다. 요구가 "설명"이면 VLM이 필요하다. **구조 선택은 성능 이전에 과제의 답 형태가 정한다**

○ 대면 실습 - 노트북의 숫자를 손으로 검산

- 노트북 1-4의 CLIP 유사도 히트맵에서 두 행을 골라 손으로 읽는다
  - 성산 일출봉 행에서 영어 장면 라벨 행렬(5/5)의 최댓값과 한국어 행렬(1/5)의 최댓값을 비교한다. 같은 사진인데 두 행렬의 "진하기"가 왜 다른가
  - 만장굴 행에서 en_coarse(4/5)가 틀린 이유를 찾는다. 0.256(동굴)과 0.246(등산로)의 차이가 0.010인데, logit_scale 100을 곱하면 확률 차이는 얼마가 되는가
- SmolVLM의 시각 토큰 수를 입력 크기별로 검산한다. 노트북 1-6에서 사진 크기를 바꿔 보면 시각 토큰 수가 어떻게 변하는지 확인하고, 7주차의 문맥 창 이야기로 연결한다

## 학습활동

**[이론]** 서로 다른 모달리티를 하나의 표현 공간에 정렬하는 원리를 정리한다. 두 인코더의 벡터 차원을 같게 맞추고 정규화해 내적하는 것, 짝이 맞는 쌍은 가깝게 하는 학습 목표, 그리고 정렬이 깨질 때(라벨 언어가 학습 데이터와 다를 때) 히트맵이 평평해지는 양상을 실측 표와 함께 쓴다

**[구현]** 노트북의 QA 예제를 받아 실행하고 **입력 이미지를 바꿔**(노트북의 TODO 한 곳) 답이 어떻게 달라지는지 확인한다. 답이 사진 내용을 따라 바뀌는지, 바뀌지 않는 사진(어두운 사진 등)에서 답이 어떻게 무너지는지를 기록한다

**[실무]** 과제 2 - **제공된 QA 골격에 모달리티 하나를 연결**한다. **해양·환경 관측 기록을 다루는 도내 기업의 조건을 상정**해(기업 데이터는 사용하지 않음) 모달리티 추가가 지연·비용에 미치는 영향을 함께 보고한다(3단계 부분점수 적용)
- 연결할 모달리티의 예: 관측 장비 사진, 기록 원문 스캔본, 관측 지점 지도
- 보고에 들어갈 항목: 시각 토큰 수(사진 크기별), 처리 시간, 문맥 창 점유율, 그리고 "이미지가 문맥을 잠식"하는 지점
- 기업 데이터는 가져오지 않는다. 조건 상정이며 실제 데이터 확보는 범위 밖이다

## 자주 하는 오해 Q&A

<details>
<summary>Q1. 멀티모달 모델은 텍스트 전용 모델보다 "똑똑한" 것 아닌가?</summary>

능력의 종류가 다르지 우열이 아니다. 사진을 보고 답하는 일은 텍스트 전용 모델이 구조적으로 못 한다(문맥에 사진이 없으니 지어낼 뿐이다). 반대로 순수 텍스트 과제에서는 멀티모달 모델이 이미지 학습에 할애한 용량만큼 손해 볼 수 있다. 과제의 입력과 답 형태가 구조를 정한다.

</details>

<details>
<summary>Q2. CLIP이 한국어 라벨을 틀리는 것은 한국어를 "몰라서" 아닌가?</summary>

부분적으로만 맞다. 한국어 라벨은 토큰으로 만들어진다(BPE 조각으로 잘리긴 하지만). 문제는 그 토큰들이 정렬 공간에서 사진 방향과 이어진 적이 없다는 것이다. 4억 쌍의 학습 데이터가 영어 위주이므로 공간 자체가 영어에 붙어 있다. 이것은 지식의 문제가 아니라 학습 데이터 분포의 문제다.

</details>

<details>
<summary>Q3. VLM의 답이 그럴듯하면 사진을 잘 본 것 아닌가?</summary>

아니다. 5주차의 false acceptance와 같은 원리로, VLM의 답도 다음 토큰 확률이 낸다. 다만 사진이 문맥에 들어가므로 지어낼 여지가 구조적으로 줄어든다(답이 사진을 따라 바뀌는 실측). 그래도 어두운 사진에서 "a black color object"로 무너지는 것처럼 근거가 약하면 답의 질도 떨어진다. 그럴듯함과 정확함은 다르다.

</details>

<details>
<summary>Q4. 이미지 1장이 832 토큰이라는 것은 왜 중요한가?</summary>

언어모형의 문맥 창은 토큰 단위로 유한하다. 사진 1장이 질문보다 수십 배 많은 토큰을 쓰므로, 사진을 여러 장 넣으면 문맥이 빨리 찬다. 7주차(장문맥)의 효율 문제가 이미지에서 먼저 나타난다. 해상도를 올리면 시각 토큰이 더 늘어나고 지연·비용도 따라 오른다.

</details>

<details>
<summary>Q5. 제로샷 분류에서 라벨을 잘 쓰면 성능이 크게 오르지 않나?</summary>

오른다. 실측에서 같은 모델, 같은 사진인데 라벨 형식만 바꿔 1/5에서 5/5로 변했다. 라벨의 언어(영어), 구체성("sunrise peak"보다 장면 묘사), 형식(한국어에 영어 괄호)이 모두 효과가 있었다. 라벨 설계는 프롬프트 설계(4주차)의 멀티모달 버전이다.

</details>

<details>
<summary>Q6. 작은 VLM(256M)을 쓰는 것은 의미가 없지 않나?</summary>

의미가 있다. 지연·비용·접근성이 완화되고, 구조(이미지가 문맥에 어떻게 들어가는가)는 큰 VLM과 같은 원리로 관찰된다. 다만 언어 능력과 세부 인지는 큰 모델보다 약하다(한국어 질문 실패, 어두운 사진 무너짐). 관찰 도구로는 오히려 좋다. 깨지는 지점이 선명하게 드러난다.

</details>

<details>
<summary>Q7. 두 인코더가 "같은 공간에 있다"는 것은 무슨 뜻인가?</summary>

두 인코더의 내부 구조가 같다는 뜻이 아니다. 내보내는 벡터의 차원이 같고(512), 벡터끼리 내적해 비교할 수 있도록 학습되었다는 뜻이다. 공간의 "좌표"는 학습으로 조정된 것이며, 정규화 뒤 내적(코사인 유사도)이 두 벡터의 유사도 역할을 한다. 두 인코더는 각자 따로 계산하고 마지막에 내적에서만 만난다.

</details>

<details>
<summary>Q8. 멀티모달 데이터는 어디서 구하지 않나?</summary>

이 과목에서는 제주 공개 데이터와 위키미디어 공용의 개방 이미지를 쓴다(이 문서 아래 사진 출처 표). 도내 기업의 데이터는 쓰지 않는다. 기업은 조건 상정으로만 등장한다. 모델과 이미지는 노트북이 실행 시점에 내려받는다.

</details>

## 스스로 점검

1. CLIP의 두 인코더는 어디에서 만나는가? 벡터 비교가 가능해지기까지의 절차를 두 단계로 써 보자.
2. logit_scale이 100.0이라는 것은 유사도 차이를 어떻게 바꾸는가? 0.256과 0.246의 차이가 확률에서는 어느 정도가 되는가 (대략적으로).
3. 한국어 라벨로 제로샷이 무너지는 원인을 "토큰화"와 "학습 데이터" 두 관점에서 구분해 써 보자.
4. 텍스트 전용 모델에게 사진을 물으면 어떤 성격의 답이 나오는가? 5주차의 어떤 개념과 같은 뿌리인가?
5. SmolVLM에 사진을 넣으면 질문 토큰보다 시각 토큰이 훨씬 많아진다(832 vs 10 안팎). 이것이 7주차로 이어지는 문제는 무엇인가?
6. 같은 한국어 질문인데 어떤 사진에서는 질문을 되풀이하고, 어떤 사진에서는 영어 답이 나왔다. 이 관찰이 말해 주는 것은 무엇인가?
7. "분류가 목적"과 "설명이 목적"일 때 어떤 구조를 고를지를 속도·문맥 비용·실패 모양과 함께 정리해 보자.
8. 이미지 모달리티를 추가하면 지연·비용이 늘어난다. 늘어나는 지점 세 가지를 써 보자.

<details>
<summary>정답 보기</summary>

1. 각자 다른 인코더에서 벡터를 만들고, 둘을 길이 1로 정규화한 뒤 내적한다. 만나는 지점은 정규화 뒤의 내적(코사인 유사도)뿐이다
2. logit_scale은 유사도의 작은 차이를 확률에서 큰 차이로 벌린다(온도의 역할). 0.010의 유사도 차이는 로짓 차이 1.0이 되고, 소프트맥스 뒤에는 몇 배 차이로 나타난다
3. 토큰화: 한국어는 BPE 조각으로 잘리지만 토큰은 만들어진다. 학습 데이터: 그 토큰이 사진 방향과 정렬된 적이 없다(영어 위주 4억 쌍). 무너지는 원인은 후자다
4. 사진을 본 적이 없으므로 언어적으로 그럴듯한 답을 지어낸다("나무 3 그루", "흰 셔츠"). 5주차 false acceptance와 같은 뿌리다. 다음 토큰 확률은 참을 보장하지 않는다
5. 이미지가 문맥 창을 잠식한다. 사진을 여러 장 넣으면 문맥이 빨리 차고, 해상도를 올리면 토큰 수가 더 늘어나 지연·비용이 커진다. 7주차 장문맥 효율의 전초전이다
6. 질문 언어가 답 언어를 정하지 않는다(한국어 질문에 영어 답). 모델이 답을 내는 능력은 학습 데이터 분포가 정한다. 질문의 언어와 답의 언어는 별개 관찰 항목이다
7. 분류: CLIP(빠름, 이미지당 벡터 1개, 실패는 무음). 설명: VLM(느림, 이미지당 수백 토큰, 실패는 그럴듯한 오답). 답의 형태가 구조를 정한다
8. (1) 시각 토큰 수 증가로 문맥 창 점유율 상승, (2) 이미지 인코더 실행 시간 추가, (3) 생성 시간 증가(긴 문맥). 사진 크기·장수에 비례한다

</details>

## 이번 주 용어 정리

| 용어 | 한 줄 뜻 |
|---|---|
| 모달리티 | 데이터의 종류(텍스트, 이미지, 음성 등). 이번 주는 텍스트와 이미지 |
| 멀티모달 모델 | 둘 이상의 모달리티를 함께 다루는 모델 |
| 쌍둥이 인코더 (dual encoder) | 이미지와 텍스트를 각자 인코딩해 벡터끼리 비교하는 구조(CLIP) |
| 인코더+디코더 (VLM) | 이미지 벡터를 언어모형 문맥에 붙여 문장을 생성하는 구조(SmolVLM) |
| 정렬 (alignment) | 서로 다른 모달리티의 벡터를 비교 가능한 하나의 공간에 놓는 것 |
| 제로샷 분류 | 분류기 학습 없이 후보 문장과의 유사도로 분류하는 방법 |
| 코사인 유사도 | 정규화된 두 벡터의 내적. 방향이 같을수록 1에 가깝다 |
| logit_scale | 유사도에 곱해지는 학습된 온도 상수. ViT-B/32 실측 100.0 |
| ViT | 이미지를 16x16 패치로 잘라 패치를 토큰처럼 보는 이미지 트랜스포머 |
| SigLIP | VLM의 비전 백본으로 쓰이는 이미지-텍스트 정렬 학습 모델 |
| 시각 토큰 | 사진이 언어모형 문맥에서 차지하는 토큰. 960x640 실측 832개 |
| 채팅 템플릿 | 대화 형식을 프롬프트로 조립하는 절차. VLM은 이미지 자리를 표시자로 둔다 |
| 근거 (grounding) | 답이 입력(사진)의 내용에 붙어 있는 것. 이미지를 바꾸면 답이 따라 바뀐다 |
| 문맥 잠식 | 이미지가 문맥 창의 대부분을 차지하는 것. 7주차로 이어진다 |
| 언어 편향 | 정렬 공간과 생성 능력이 학습 데이터의 언어(영어)에 붙는 것. 한국어 라벨·질문에서 드러난다 |
