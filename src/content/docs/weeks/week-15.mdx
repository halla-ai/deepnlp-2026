## 온라인 (2시수)

### 강의: 최종 발표를 주장과 근거의 연결로 설계하기

□ 발표에서 먼저 해결할 문제

- "제주 안내 답변 생성 성공"이라는 문장만으로는 누구에게 어떤 도움이 되는지 판단 곤란
- 같은 답변이라도 관광 문서 탐색 보조와 안전·자격 판단 자동화는 영향 범위가 다른 서비스
- 먼저 고정할 항목: 대상 사용자, 해결할 질문, 허용한 자료, 자동화할 범위, 사람이 확인할 지점
- 그다음 선택 이유 제시: 9주차 검색 결합이 필요한 이유, 5주차 평가가 확인한 대상, 12주차 판단 보류 조건
- 모델 이름 나열보다 **입력에서 사용자의 행동까지 연결되는 경로** 제시

□ 주장(claim)과 근거(evidence)의 범위

- 주장: 청중에게 사실로 받아들이도록 요청하는 문장
- 근거: 그 문장이 성립하는 조건을 확인할 수 있는 출처·실행 기록·비교 결과
- 범위: 자료 판, 입력 집합, 실행 환경, 비교 기준, 미측정 항목
- "모든 질문에 정확"이라는 주장은 유한한 몇 질문의 데모보다 넓은 범위
- 정직한 축소: "고정 판의 공개 문서와 선택한 질문에서 근거 구절 출력 확인. 다른 문서·질문에서의 성능 미측정"
- 결과물이 작은 것과 근거가 없는 것은 다른 상태. 작은 결과라도 경계가 명확하면 검토 가능한 성과

- 관찰 질문: 그림의 '근거' 상자에 화면 캡처 하나만 넣으면 빠지는 조건 예측

<Image src={story} width={1200} alt="사용자 문제에서 제한한 주장으로, 코드·자료·입력·출력·조건 근거 묶음으로, 미측정 범위와 다음 확인으로 이어지는 발표 구조" />

- 그림 해석: 한 출력 화면은 출력의 존재를 보여 주지만 데이터 판·비교의 공정성·재현 조건까지 자동으로 증명하지 않는 구조

□ 같은 결과를 세 수준으로 표현하는 예

| 발표 문장 | 검토 | 수정 방향 |
|---|---|---|
| 제주 관광 질문을 모두 해결 | 몇 질문의 실행으로 전체 범위 입증 불가 | 실제 확인한 자료·질문 범위 명시 |
| 선택 질문에서 근거 구절이 함께 출력 | 기록과 문장이 일치하면 제한된 관찰 주장 가능 | 코드 판·입력·출력 연결 |
| 검색 점수가 높으므로 답이 사실 | 검색 점수와 사실 정확도의 평가 대상 차이 | 사실 확인과 검색 순위의 분리 |

- 9주차의 문자열 프록시 점수는 일치 단어를 측정하는 도구. 사용자 만족도나 사실 정확도로 치환 금지
- 11주차의 과정 점수는 제공된 단계 라벨에 관한 관찰. 프로젝트 전체 추론 신뢰성의 증거로 확대 금지
- 12주차의 설명 일치도는 내부 충실성의 직접 측정이 아님

□ 주장·근거 등록표, 복사해서 팀 자료로 채우기

```text
주장 ID: C1
대상 사용자·질문:
발표할 한 문장:
공개 자료 URL·판·라이선스:
코드 판 또는 변경 기록:
입력 집합·비교 기준:
실행 환경·실행 시점:
근거 파일·출력 위치:
이 근거로 말할 수 있는 범위:
미측정·실패·판단 보류:
다음 확인과 담당 역할:
```

- 근거 파일은 실제 파일 경로로 연결. 존재하지 않는 실행 결과를 예정 결과로 채우지 않는 작성
- 담당 역할은 데이터·검색·평가·운영 등 역할명으로 기록. 학생 공개 폴더는 학번만 사용

### 강의: 20분 이야기와 데모 실패 대응

□ 시간 배분의 계산

- 정본의 팀별 발표: **20분 발표, 10분 Q&A**
- 발표 시간 `T = P + D + E + M + L`
  - `P`: 문제와 사용자, `D`: 설계와 선택 이유, `E`: 비교와 근거
  - `M`: 데모와 실패 대응, `L`: 한계와 다음 단계. 모든 항의 단위는 분
- 작성 예시: `T = 3 + 4 + 5 + 5 + 3 = 20분`
- Q&A 포함 한 팀의 예시 묶음: `20 + 10 = 30분`
- 수업의 1시수 대면과 여러 팀의 발표를 모두 같은 시간표에 끼워 넣는 계산은 미완성. 전체 팀 운영 일정·순서는 별도 수업 공지 확인

| 구간 | 작성 배분 | 반드시 남길 연결 |
|---|---:|---|
| 문제·사용자 | 3분 | 누구의 어떤 행동을 돕는지 |
| 설계·선택 이유 | 4분 | 학기 개념과 설계 결정 연결 |
| 비교·근거 | 5분 | 기준·조건·결과·미측정 |
| 데모·실패 대응 | 5분 | 현재 실행과 과거 기록 구분 |
| 한계·다음 단계 | 3분 | 남은 위험과 가장 작은 다음 검증 |

□ 24분 리허설을 20분으로 줄이는 예

- 최초 기록: `4 + 6 + 5 + 6 + 3 = 24분`, 초과 `24 - 20 = 4분`
- 반복 배경 설명 1분, 중복 구조 설명 2분, 같은 입력의 데모 반복 1분 축소
- 수정 결과: `3 + 4 + 5 + 5 + 3 = 20분`
- 비교 근거와 한계를 지우는 축소는 청중의 판단 재료를 제거하는 선택
- 배분표는 계획. 실제 리허설에서 시작·끝 시각을 다시 기록해야 경과 시간 확인 가능

□ 재현 가능한 데모 묶음

- 입력: 실제 질문·고정 자료 판·검색 설정
- 실행: 코드 판, 필요한 라이브러리, CPU 환경, 실행 명령 또는 셀 순서
- 출력: 근거 구절, 답 또는 판단 보류, 오류, 경과 시간
- 해석: 확인한 것과 확인하지 않은 것
- 재현의 뜻: 같은 기록된 조건에서 결과를 다시 확인할 수 있는 상태. 같은 화면을 보여 주는 행위만으로 충족되지 않는 조건

- 관찰 질문: 인터넷이 끊겼을 때 과거 녹화로 바꾸면 무엇을 먼저 공개해야 하는지 예측

<Image src={states} width={1200} alt="데모 정상 상태는 현재 입력·출력 기록, 실패 상태는 실패 공개와 과거 실행 조건 표시, 실행 근거 없는 상태는 판단 보류와 재실행 계획으로 나뉘는 도식" />

- 그림 해석: fallback은 성공을 가장하는 기능이 아니라 설명을 계속하면서 증거 상태를 유지하는 방법

□ 정상·실패·보류를 모두 준비하는 양식

```text
정상: 현재 입력 / 출력 / 조건 / 경과 시간 / 확인 범위
실패: 현재 실패 증상 / 중단 지점 / 안전한 중단 또는 보류
대체 기록: 과거 실행 날짜 / 코드 판 / 입력 / 출력 / 현재와 다른 조건
보류: 실행 근거 없는 주장 / 말하지 않을 수치 / 재확인 절차
```

- 실패 중단 후 원인을 모르면 "통신 오류로 추정, 미확인"처럼 관찰과 가설 분리
- 이전 결과를 사용할 경우 "현재 실행 실패, 이전 실행 기록" 표시
- 실행 기록이 없으면 구조·예정 절차까지만 설명. 가상 결과를 실측 그래프로 표현 금지

### 강의: 산업 응용을 운영 조건으로 읽기

□ 공개기관 자료가 보여 주는 단계

- NIA 가이드 소개: 서비스 정의에서 예산·계약·구현을 거쳐 운영·고도화로 진행하는 단계 구분
- 도입 목적은 모델 실행 자체보다 행정 수요와 서비스 필요성 검토
- 소개 페이지의 운영 항목: 성능 모니터링과 지속적인 데이터 업데이트 방안
- 이는 공공부문 도입 안내의 확인된 내용. 특정 도내 기업의 실제 운영 상태나 채용 수요의 증거는 아님
- 상정 산업 응용에서도 같은 질문 적용 가능: 누구의 수요인지, 어떤 권한으로 어떤 데이터를 쓰는지, 누가 업데이트와 오류를 책임지는지

□ 제주 공개 문서 탐색 보조 서비스의 상정 조건

- 입력 자료: 수업에서 허용한 제주 공개 문서. 조직 내부 자료·행정 내부망 접근 없음
- 목적: 관련 문서와 근거 구절 탐색 보조
- 사용자: 문서를 확인하는 담당자를 상정. 실제 기관 도입·제휴·계약 사실 없음
- 경계: 안전 판단이나 자격 판정을 자동으로 확정하지 않고 출처 확인·사람 검토 유지
- 팀이 실제로 한 작업: 구현한 검색 함수, 실행한 입력, 측정한 지표와 실패 기록만 명시

| 관점 | 상정 운영 질문 | 팀이 보여 줄 수 있는 근거 | 아직 말할 수 없는 주장 |
|---|---|---|---|
| 사용자 | 답보다 원문 확인이 필요한지 | 원문 링크·근거 구절 출력 | 실제 사용자 만족도, 미조사 시 |
| 데이터 담당 | 자료 변경을 어떻게 감지하는지 | 고정 판과 갱신 절차 | 모든 자료의 최신성 |
| 운영 담당 | 실패·시간 초과 때 무엇을 반환하는지 | 오류·보류 경로와 재실행 기록 | 장기 운영 안정성, 미운영 시 |
| 예산 담당 | 호출·검토 부담이 얼마인지 | 조건이 적힌 계산·실측 | 실제 예산 승인이나 절감 성과 |

□ 운영 부담의 작은 계산

- 작성 상정: 하루 요청 `R = 40건`, 사람이 확인해야 하는 비율 `q = 0.25`, 검토 시간 `t = 3분/건`
- 사람 검토 부담 `H = R × q × t = 40 × 0.25 × 3 = 30분/일`
- 자료 변경으로 `q = 0.5`가 되면 `H = 40 × 0.5 × 3 = 60분/일`
- 요청 수가 같아도 판단 보류·확인 비율 증가로 운영 부담 두 배
- 위 숫자는 작성 예시. 실제 사용자 요청 수·검토 시간·기관 비용 실측 아님
- 계산에 미포함: 데이터 갱신, 장애 분석, 컴퓨팅 비용, 교육, 보안 검토. 30분을 전체 운영비로 부르는 결론 금지
- 14주차 기록과 연결: 측정한 지연·호출 수는 계산에 넣되 미측정 사람 시간은 가정으로 남기는 방식

### 강의: 학기 개념 위계와 도내 정주 진로 로드맵

□ 개념을 순서가 아니라 의존 관계로 다시 보기

- 1~3주차: 아키텍처·학습 루프·미세조정으로 구현 선택의 기반 마련
- 4~7주차: 문맥·평가·멀티모달·장문맥으로 입력과 출력의 조건 검토
- 8주차: 중간고사와 PEFT 심화, 기반 이해의 확인
- 9~12주차: 검색 근거·정렬·과정 감독·책임 있는 AI로 결과를 사용할 경계 설계

- 14주차: 운영 조건과 측정·실패 대응을 프로젝트로 연결
- 15주차: 확인한 범위의 발표, 질문, 회고와 다음 증거 계획

- 관찰 질문: 검색 기능을 만들었어도 평가와 위험 경계를 설명하지 못하면 어떤 발표 질문에 답하지 못하는지 예측

□ 1주차 사전 진단과 지식 변화의 실물 기록

```text

```

- "알게 됨"만 체크하면 자기 느낌과 설명 능력 구분 곤란
- 예: 처음에는 검색 점수와 사실 정확도의 차이를 설명하지 못한 상태
- 지금의 증거: 9주차 오탐 출력과 5주차 지표 정의를 연결해, 단어 일치가 정답을 보장하지 않는 이유를 설명한 기록
- 다른 문서에서 재현하지 않았다면 그 조건은 여전히 미확인으로 남기는 회고

□ 역량 간격을 성격 평가보다 증거 계획으로 바꾸기

- 도내 정주 경로: 제주에서 지속적으로 서비스를 만들고 운용한다는 개인 목표를 기준으로 현재 역량과 상정 요구 조건의 간격 정리
- "AI를 잘함"은 넓은 자기 평가. "고정 자료로 검색 결과를 재현하고 실패를 분류함"은 확인 가능한 증거
- 간격: 상정 서비스에 필요한 행동 중 현재 증거로 보여 주지 못하는 부분
- 현재 결과물을 폐기하고 큰 프로젝트를 새로 만드는 방식보다 **다음 작은 증거**를 정하는 방식
- 실제 채용 요건·수요·급여·취업 보장에 대한 주장 없음. 특정 공고를 검토한다면 발행 기관·날짜·요건을 별도 확인해야 하는 항목

- 관찰 질문: "모델 학습 경험 없음"보다 "자료 갱신 후 같은 질문의 근거 변화 검증 없음"이 다음 활동을 더 구체화하는 이유 예측

<Image src={career} width={1200} alt="현재 증거에서 상정 서비스의 요구 행동과 비교해 미확인 간격을 찾고, 다음 작은 실행 기록으로 연결하는 진로 로드맵. 실제 기업 채용 기준이나 취업 보장 아님" />

- 그림 해석: 확인하지 않은 채용 수요를 단정하지 않고, 자신의 결과물에서 다음 학습 단위를 찾는 구조

| 현재 갖춘 증거 | 상정 운용·서비스 조건 | 미확인 간격 | 다음 작은 증거 제출 단위 |
|---|---|---|---|
| 고정 문서 검색 결과 | 문서 갱신 후 근거 변화 확인 | 갱신 비교 미실행 | 두 판의 동일 질문 출력 비교표 |
| 정상 실행 화면 | 실패 때 사용자에게 상태 안내 | 실패 경로 미확인 | 실패 입력 1개·보류 출력·복구 기록 |
| 자동 지표 표 | 사람이 원문 확인할 근거 제공 | 오탐 해석 미기록 | 오탐 1건의 원문 대조 설명 |
| 팀 코드 일부 구현 | 인수인계 가능한 실행 절차 | 다른 사람 재실행 미확인 | 역할별 재실행 기록과 누락 조건 |

- 위 표는 작성 예시. 모든 학생에게 같은 진로를 추천하는 목록 아님
- 각자 실제 증거, 원하는 역할, 지역에서 지속할 수 있는 학습·운용 조건으로 한 행 이상 작성
- 역할 피드백 양식: `검토 역할 / 확인한 근거 / 재현 누락 / 다음 확인 / 아직 모르는 것`
